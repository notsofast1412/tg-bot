# Монитор цен на краску

Python 3.12+, aiogram 3, SQLAlchemy 2, Alembic, SQLite. Управление только владельцем
в личном чате; Telegram-группа используется исключительно для уведомлений.
Docker, Redis и внешняя база не нужны.

Для Ubuntu 26.04 и переноса с Windows используйте
[пошаговую установку на сервер](docs/SERVER_DEPLOYMENT.md). Она создаёт отдельный
Python 3.12.14 и не меняет системный Python. С текущим lockfile установщик
принимает Python 3.12/3.13; новые системные версии автоматически не используются.

**Текущий статус:** поддерживаются только WB и Ozon. Telegram на домашней
Ubuntu 22.04 работает. Браузерная проверка WB подтвердила карточку 518397236,
вариант 716573024: `price.product=26300` (263 ₽), остаток 52 на момент проверки.
Этот источник подключён к добавлению и мониторингу; установку обновлённого бота
на VM нужно проверить командой `scripts.manage probe` и добавлением товара.
Ozon остаётся на HTTP-адаптере и возвращает 403 для проверенной карточки.

## Первая установка на Ubuntu 22.04/24.04

Для нового сервера и отсутствующего каталога `/opt/paintbot`:

```bash
sudo apt-get update
sudo apt-get install -y git ca-certificates
sudo git clone https://github.com/notsofast1412/tg-bot.git /opt/paintbot
sudo bash /opt/paintbot/scripts/bootstrap_ubuntu.sh
```

Bootstrap устанавливает отдельный Python 3.12.14, Google Chrome из подписанного
официального APT-репозитория, Xvfb и xauth. Системный Python не заменяется.
Существующие установки обновляются по [инструкции](docs/OPERATIONS.md).

`scripts/install.sh` запускается от пользователя приложения: создаёт `.venv`
для бота и `.browser-probe` для Playwright, устанавливает зависимости из
`requirements.lock` и `requirements-browser.lock`, применяет миграции,
идемпотентно добавляет 16 тегов и запускает тесты. `.env` не перезаписывается.
На существующей VM, где Chrome/Xvfb уже установлены, повторно ставить их не нужно.
Подробности браузерного источника: [WB](docs/WB_DIAGNOSTICS.md).

## Telegram и конфигурация

1. Создайте бота в официальном **@BotFather** командой `/newbot`.
2. Сохраните токен **только** в защищённом `.env` (файл из `.env.example`),
   `BOT_TOKEN=…`. Не отправляйте токен в чат, Git или журналы.
3. В `OWNER_ID` укажите числовой ID своего личного аккаунта. Его можно узнать
   через доверенный способ получения Telegram ID; username не подходит.
4. `GROUP_ID` необязателен: оставьте пустым и настройте через `/setgroup` в
   личном чате. Бот проверит `getChat` и `getChatMember` перед сохранением.
5. Добавьте бота в группу. Дайте право отправлять сообщения. Права
   администратора не требуются, если обычным участникам разрешена отправка.
   Privacy mode можно оставить включённым: сообщения группы не обрабатываются.
6. Узнайте ID группы через доверенный Telegram-клиент/бота. Для супергруппы он
   обычно имеет вид `-100…`. Не используйте ID личного чата или канала.

```bash
sudo chmod 600 /opt/paintbot/.env
sudo -u paintbot sh -c 'cd /opt/paintbot && .venv/bin/python -m paintbot'
```

Токен должен быть реальным значением, читаемым локально библиотекой aiogram,
а не произвольной строкой-заглушкой сетевого прокси. При использовании облачных
настроек вводите его в защищённом поле переменной `BOT_TOKEN`; не записывайте
значение в setup-скрипт. Telegram, WB и Ozon используют прямые соединения. Настройки прокси из `.env`
и переменных окружения игнорируются; проверка TLS сохраняется.

При настроенном webhook приложение остановится, не меняя существующую
интеграцию. Отключите webhook через доверенный Telegram API-клиент, если переход
на long polling намеренный. Одновременный polling с другого сервера также нужно
остановить. Локальный файловый lock предотвращает два процесса для одной базы.

## Служба и резервные копии

После успешного ручного запуска остановите его и установите units:

```bash
sudo cp /opt/paintbot/systemd/paintbot.service /opt/paintbot/systemd/paintbot-backup.service /opt/paintbot/systemd/paintbot-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now paintbot.service paintbot-backup.timer
sudo systemctl status paintbot.service
sudo journalctl -u paintbot.service -n 100 --no-pager
```

Служба перезапускается при сбое; timer создаёт ежедневные согласованные SQLite
backup через SQLite Backup API и хранит 30 последних файлов. База, журнал,
lock и backups по умолчанию лежат в `/opt/paintbot/var`. Файловые логи ротируются:
5 файлов по 5 MB плюс текущий файл. При смене `DATABASE_PATH` измените
`ReadWritePaths` в обеих службах. При постоянном сбое конфигурации после 10
запусков за 5 минут сработает ограничение systemd: исправьте причину и выполните
`sudo systemctl reset-failed paintbot`, затем `start`.

Ручная резервная копия:

```bash
cd /opt/paintbot
sudo -u paintbot bash scripts/backup.sh
```

Переносите копии на отдельное хранилище. Они содержат URL и настройки владельца,
но токен в базе не хранится. [Восстановление и обновление](docs/OPERATIONS.md).

## Использование

В личном чате владельца: `/start`. Кнопка добавления предлагает ссылку или
артикул. Для ссылок отправляйте до 50 URL одним/несколькими сообщениями, затем
«Готово»: карточки → общее название → уточнения характеристик → тег/его порог →
сводка → подтверждение. Порог выбирается из правил тега; изменить его можно
через «Теги и пороги». Это общее правило для всех товаров тега.

Поддерживаются также короткие ссылки Ozon `https://ozon.ru/t/…`: бот раскрывает
их только через разрешённые HTTPS-адреса Ozon и сохраняет прямую карточку.
Не добавляйте к ссылке время сообщения и другой текст без пробела. Например,
окончание `14:20`, приклеенное к коду ссылки, не удаляется автоматически.

Для WB сохраняется выбранный `?size=…`: цена допускается только при совпадении
этого значения с единственным `chrtId` или `optionId` в ответе API. Варианты имеют разные
идентификаторы мониторинга. Старый прямой API больше не используется:
цена берётся из ответа, полученного самой страницей WB в обычном Chrome.
Playwright подключается через локальный DevTools, открывает карточку и читает ответы страницы.

Поддерживаются только WB и Ozon. Артикулы — числовой ID карточки.
После обновления ранее сохранённые товары других площадок автоматически
отключаются; история цен сохраняется, ожидающие уведомления отменяются. Произвольный артикул продавца нельзя однозначно
преобразовать в карточку без дополнительного источника; такой ввод отклоняется,
предлагается прямая ссылка. Никакого поиска похожих товаров нет.

Доступная карточка без достоверной цены добавляется в ожидании. Цена предпросмотра
не используется для мониторинга: после сохранения выполняется новая проверка.
Цвет, объём и количество не выводятся из тега/названия. Неизвестные характеристики
можно явно уточнить; они сохраняются отдельно как сведения владельца.

- `/list market=wb tag=#arton status=error` — фильтры и страницы по 5 товаров.
- `/tagitems #arton`, `/history ID`, `/pause ID`, `/resume ID`.
- `/tags` — пороги; `/setgroup`, `/settings` — настройки.
- `/status` — фактическая диагностика; кнопка тестовой отправки сразу отправляет
  отдельное сообщение в группу без изменения цен и уведомлений.
- `/check` — проверка только уже наступивших заданий, без сброса rate limit.
- `/queue`, `/retry ID` — проблемные доставки и подтверждённый ручной повтор.
- `/cancel` и кнопка отмены сбрасывают черновик. После перезапуска незавершённые
  сценарии безопасно сбрасываются; сохранённые товары остаются.

Время показывается по Москве. Цены хранятся целыми копейками, без конвертации.
Порог строгий: 400 ₽ не ниже 400 ₽, 399 ₽ ниже. Первая подтверждённая цена ниже
порога вызывает событие. Пока цена остаётся ниже, новых событий нет. Ошибка
получения данных не сбрасывает это состояние.

Изменение порога пересчитывает базовое состояние по последней известной цене
без рассылки и отменяет неотправленные события этого тега. Для ещё не проверенного
товара действует обычное правило первого успешного наблюдения.

## Разработка

```bash
bash scripts/install.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.manage status
.venv/bin/python -m scripts.manage probe 'https://www.wildberries.ru/catalog/ID/detail.aspx'
```

`probe` делает реальные сетевые запросы и возвращает ненулевой код, если цена
не подтверждена. Используйте существующие ссылки на свои товары; случайный ID
не доказывает доступность/недоступность каталога. Автотесты изолированы от сети,
используют временные БД, мок-транспорт и синтетические ответы. SQLite migrations
запускаются без Telegram-токена. Структура модулей следует ТЗ: `paintbot/bot`,
`services`, `marketplaces`, `database`, `scheduler`, `config`; отдельно `migrations`,
`scripts`, `systemd`, `tests`, `docs`.
