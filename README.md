# PaintWatch — мониторинг цен на Wildberries и Ozon

Telegram-бот для выбранных владельцем карточек краски. Управление доступно только владельцу в личном чате, уведомления приходят в отдельную группу. Яндекс Маркет исключён по уточнению владельца. Автоматического поиска товаров и аналогов нет.

**Состояние интеграций:** на карточке Ozon `196525150` фактически получены SKU, название, продавец, цвет и цена по карте **655 ₽** (обычная — 718 ₽, только справочно). Это результат разовой проверки 19.10.2026 МСК, не обещание текущей цены. WB `29220564` в этой среде возвращает HTTP 403 на API и 498 с WBAAS AntiBot на странице; мониторинг WB пока не подтверждён. CAPTCHA, авторизация и ограничения доступа не обходятся. Реальная доставка в Telegram пока не проверена: токен и ID владельца недоступны текущему процессу. Подробности: [отчёт проверок](docs/validation.md), [разбор причин](docs/wb-investigation.md).

## Возможности

- Добавление по прямым ссылкам или числовому ID карточки (WB nmID, Ozon SKU); для артикула обязательны выбор площадки и подтверждение предпросмотра.
- Пакет ссылок, включая URL без пробелов и сообщения подряд: проверка, название пакета, тег, общий/индивидуальный порог, уточнение характеристик, итоговое подтверждение. Дубликаты внутри пакета и в базе пропускаются.
- `/cancel`, кнопки отмены, тайм-аут сценария. Незавершённый сценарий хранится в SQLite, после перезапуска продолжается до истечения тайм-аута. Повторное сохранение не создаёт повторных товаров.
- Все 16 тегов из ТЗ, идемпотентная инициализация. Написание `#joggle`, `#2jiggle`, `#6jiggle` сохранено буквально. Упаковка из тега не вычисляется.
- Строгое сравнение `<`; первое успешное получение цены ниже порога создаёт уведомление. Повтор возможен после выхода из условия и нового снижения. Ошибки состояние не сбрасывают.
- История хранит изменения цены; журнал попыток — успешные и неуспешные проверки отдельно. Денежные суммы — целые копейки RUB без скрытой конвертации.
- Интервал по умолчанию 10 минут, ограничения частоты, тайм-ауты и до двух HTTP-попыток при временных сетевых/серверных ошибках. После ошибок — экспоненциальная пауза до суток. `/check` не обходит интервалы.
- Постраничный список с совместимыми фильтрами по площадке, тегу и статусу, пауза товара, индивидуальный порог, история и диагностика.
- Транзакционная очередь уведомлений, защита от параллельного запуска, ротация журналов, ежедневный SQLite backup и systemd.

## Правила цен и доставки

**Ozon:** по указанию владельца мониторится `webPrice.cardPrice`, то есть цена по карте/указанному Ozon способу оплаты. Обычная `price` показывается справочно; если `cardPrice` отсутствует или не подтверждена, обычная цена не подставляется. Доступность оплаты и регион могут влиять на итоговую цену.

**WB:** `sizes[].price.product` для конкретной карточки/размера, регион `WB_DEST`, без скидки WB Кошелька. Если размер неоднозначен, нужна ссылка с `?size=optionId`. Старые `basic`/`priceU` не используются как текущая цена. `volume` из API не считается остатком или объёмом упаковки.

Изменение порога пересчитывает состояние относительно последней достоверной цены и отменяет ещё не отправленные события старого порога. Само изменение настройки не вызывает рассылку. Индивидуальные пороги не меняются при редактировании тега.

На переход создаётся одна запись `(product_id, generation)`, атомарно с историей и состоянием. При недоступности API до отправки и явном Telegram `RetryAfter` повтор автоматический. Ошибки группы ждут исправления настроек. Если запрос отправлен, но ответ потерян, Bot API не позволяет гарантировать однократную доставку: событие получает статус `uncertain`, а не повторяется вслепую. Проверьте группу по номеру события, затем `/retry ID` с отдельным подтверждением. После аварии события `sending` также становятся `uncertain`. Это ограничение внешнего API, а не доказательство доставки.

## Быстрый запуск для разработки

Нужен Python 3.12 (Ubuntu 24.04). Работайте в существующем checkout; отдельный Git worktree для облачной задачи не нужен.

```bash
cd /workspace/tg-bot  # либо каталог проекта на вашем компьютере
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-dev.lock
cp .env.example .env
chmod 600 .env
```

В защищённом редакторе заполните `BOT_TOKEN` и положительный `OWNER_ID`. Не присылайте токен в чат, не добавляйте `.env` в Git. После этого:

```bash
.venv/bin/python -m paintwatch.cli init-db
.venv/bin/python -m paintwatch.main
```

Тесты и локальная диагностика не требуют Telegram-токена:

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/python -m paintwatch.cli doctor
.venv/bin/python -m paintwatch.cli probe 'https://www.ozon.ru/product/196525150/'
```

`probe` делает реальные read-only запросы: код 0 — подтверждена отслеживаемая цена, код 2 — цена не получена/неоднозначна/доступ ограничен. Моки в автоматических тестах не доказывают доступность площадок. `doctor` проверяет базу и наличие настроек, но не утверждает, что процесс бота или Telegram доступны.

## Создание бота и группы

1. Создайте бота у официального `@BotFather` командой `/newbot`. Сохраните токен в `.env` или в секретах среды.
2. Укажите свой числовой Telegram user ID как `OWNER_ID`. Для определения ID используйте доверенный инструмент/свой Telegram-клиент; username вместо ID не принимается.
3. Добавьте бота в группу для уведомлений и разрешите отправлять сообщения. Privacy mode отключать не требуется, команды в группе игнорируются.
4. Получите числовой ID группы (обычно `-100…` для супергруппы) через Telegram Bot API/клиент и в личном чате владельца отправьте `/setgroup -100…`. Для первичного запуска можно вместо этого задать `NOTIFICATION_CHAT_ID` в `.env`. Известная боту настройка в SQLite имеет приоритет над переменной.
5. Нажмите «🔌 Диагностика» для фактических `getMe/getChat/getChatMember`. Нажмите «📨 Проверить отправку в группу»: сообщение отправляется сразу, результат показывается после попытки.
6. Добавьте свои товары. Если цена при сохранении уже ниже порога, событие попадёт в очередь для группы. Без настроенной группы очередь сохраняется, но не отправляется.

Если на токене настроен webhook, запуск polling завершится с объяснением. Отключите webhook явно после проверки, что другой сервис не использует этого бота. Приложение не удаляет его и не сбрасывает pending updates автоматически.

## Установка на Ubuntu Server 22.04 / 24.04 LTS

Для Ubuntu 22.04 сначала установите Python 3.12 по [пошаговой инструкции](docs/ubuntu-22.04.md). В ней также описаны клонирование из GitHub, запуск службы и проверка уведомлений в группе. Системный Python 3.10 заменять не нужно.

После сохранения исходников этого проекта разместите их в `/opt/paintwatch`. Если используете Git, убедитесь, что нужная версия кода уже находится в удалённом репозитории. Установщик не загружает код и не запускает бота с пустым токеном.

```bash
cd /opt/paintwatch
sudo bash scripts/install.sh
sudoedit /opt/paintwatch/.env
sudo systemctl enable --now paintwatch
sudo systemctl status paintwatch
```

Установщик создаёт пользователя `paintwatch`, venv, каталоги данных, применяет миграции и устанавливает unit. Существующий `.env` не перезаписывается. Исходники остаются доступными только для чтения службе; `data/` и `logs/` принадлежат службе. Зависимости устанавливаются из `requirements.lock` с обязательной проверкой хешей и TLS. Docker, Redis, APScheduler и отдельные серверы не нужны: используется асинхронный планировщик с `next_check` в SQLite.

Ориентир для небольшой базы — 2 vCPU, 2 GB RAM, SSD 30 GB. HTTP-методы предпочтительнее Chromium по расходу памяти. Фактическая нагрузка зависит от числа товаров; 10 минут — целевой минимальный интервал, не гарантия допустимости для каждой площадки. Если правила/ответы площадки требуют реже, увеличьте `WB_INTERVAL`/`OZON_INTERVAL` и перезапустите службу.

### Необязательный Playwright

По умолчанию выключен. Резервный рендеринг применяется при отсутствии ожидаемой структуры, но не после CAPTCHA/HTTP 401/403/429/498. TLS-проверка не отключается, stealth-настройки и ротация IP для обхода защиты не используются.

```bash
cd /opt/paintwatch
sudo .venv/bin/python -m playwright install-deps chromium
sudo -u paintwatch env PLAYWRIGHT_BROWSERS_PATH=/opt/paintwatch/data/browsers \
  .venv/bin/python -m playwright install chromium
```

Затем задайте `BROWSER_ENABLED=true` в `.env` и перезапустите службу. Unit устанавливает путь браузеров внутри `data/`. При использовании уже установленного Chromium можно задать `CHROMIUM_PATH`; совместимость конкретной системной версии нужно проверить. Для Ozon общий JSON-LD не подтверждает цену по карте: резервный метод может подтвердить карточку, оставив цену неизвестной.

## Обслуживание

```bash
sudo journalctl -u paintwatch -n 100 --no-pager
sudo -u paintwatch bash scripts/diagnose.sh
sudo -u paintwatch bash scripts/backup.sh
```

Файловый журнал: `logs/paintwatch.log`, до 5 MB и 5 архивов. Токены и пароли прокси маскируются. Приложение создаёт согласованный backup через SQLite Backup API при запуске и затем раз в сутки, оставляет 14 автоматических копий в `data/backups/`. Ручные копии не удаляются. Для устойчивости к потере диска переносите копии на отдельный носитель с ограниченными правами.

Обновление: остановите службу, сделайте backup, обновите исходники, установите зависимости с хешами, примените миграции от пользователя службы, затем запустите её. Сохраните `.env`, `data/` и `logs/`; не выполняйте `git clean -xfd` в рабочей установке.

```bash
sudo systemctl stop paintwatch
sudo -u paintwatch bash scripts/backup.sh
# Здесь обновление исходников выбранным вами способом.
sudo .venv/bin/python -m pip install --require-hashes -r requirements.lock
sudo -u paintwatch .venv/bin/python -m paintwatch.cli init-db
sudo systemctl start paintwatch
```

Восстановление и типичные ошибки: [эксплуатация](docs/operations.md). Сведения об адаптерах и сетевых адресах: [адаптеры](docs/adapters.md).

## Структура

```text
paintwatch/
  bot/ui.py               # авторизация, интерфейс, пакетный сценарий
  database/models.py      # SQLAlchemy-модели
  database/store.py       # транзакции, история, теги, outbox, backup
  marketplaces/           # WB/Ozon, HTTP, JSON-LD, Playwright
  services.py             # сбор пакетов и планировщик
  notifications.py        # сообщения в группу и повторная доставка
  diagnostics.py          # фактические проверки Telegram
  config.py               # Pydantic Settings
  main.py                 # единый процесс и graceful shutdown
  cli.py                  # миграции, probe, диагностика, backup/restore
migrations/               # Alembic, схема версии 0001
tests/                    # бизнес-логика, транспорт, интерфейс, миграции
scripts/                  # установка, диагностика, backup
systemd/                  # служба для Ubuntu
docs/                     # ограничения и результаты проверок
```

При проектировании использованы идеи из предоставленных статей Amvera (HTTP JSON WB, разделение сбора/аналитики, Playwright) и репозиториев [Tleukhanov/WB_parser](https://github.com/Tleukhanov/WB_parser) (`b5930fd`), [nickisnotgaara/ozon-parser](https://github.com/nickisnotgaara/ozon-parser) (`d479a08`). Реализация написана для этого ТЗ: вместо поиска каталога отслеживаются конкретные карточки, исправлены неоднозначность цены, обработка остатков и состояние уведомлений.
