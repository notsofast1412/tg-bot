# PaintWatch 0.4.2 для Windows

Мониторинг выбранных карточек Wildberries и Ozon на домашней Windows-виртуалке, включая Proxmox. Управление — в окне программы и личном чате Telegram; ценовые уведомления приходят в группу, сообщения о проблемах — владельцу в ЛС.

## Запуск

**Готовая сборка:** GitHub → **Actions → Windows application → успешный запуск → Artifacts → PaintWatch-Windows-x64**. Распакуйте весь архив в постоянный каталог, например `C:\Apps\PaintWatch`, и запустите `PaintWatch.exe`. Не переносите EXE без папки `_internal`. Артефакт появляется только после успешного workflow; наличие исходников не подтверждает готовность сборки.

**Из исходников:** установите Python 3.12 x64 с python.org (launcher и Tcl/Tk), скачайте ZIP репозитория и распакуйте. В PowerShell из каталога проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\run.cmd
```

Нужен обычный Google Chrome или Microsoft Edge с расширением из папки `extension`. Готовому EXE Python не нужен. В версии 0.3 сбор по умолчанию выполняется через расширение в обычном браузере, а не через управляемый профиль Playwright. Для ссылок добавлены кнопка «Вставить из буфера», меню по правой кнопке и Ctrl+V с русской раскладкой.

## Первое использование

1. В «Настройках» задайте токен бота, отрицательный ID Telegram-группы и интервал в секундах: от 1 секунды, либо `0` для непрерывного обхода. Добавьте бота в группу и разрешите отправку сообщений.
2. Сохраните настройки, нажмите «Проверить доступ Telegram», затем «Отправить тест в группу». Убедитесь, что сообщение пришло.
3. Добавьте до 1000 прямых ссылок или числовых артикулов, выберите тег и при необходимости индивидуальный порог. Дубликаты пропускаются.
4. Установите расширение по инструкции ниже и подключите его кодом из настроек приложения.
5. Нажмите «Запустить» и держите обычный браузер открытым. По умолчанию проверяются 4 карточки одновременно; настройка допускает 1–32. Цена читается сразу после появления, без ожидания изображений. Лимит одной проверки — 20 секунд по умолчанию (настраивается от 1 до 120). При CAPTCHA пройдите проверку сами и нажмите «Я прошёл проверку». Пауза HTTP 429 сохраняется.

## Подключение расширения

1. В приложении откройте «Настройки» → «Открыть папку расширения».
2. В обычном Chrome откройте `chrome://extensions`, включите «Режим разработчика», нажмите «Загрузить распакованное расширение» и выберите эту папку `extension`. Для Edge используйте `edge://extensions`.
3. В PaintWatch нажмите «Скопировать код». Откройте окно расширения PaintWatch через значок пазла в браузере, вставьте код и нажмите «Подключить».
4. В настройках приложения должен появиться статус «Расширение подключено». Добавьте товары и включите мониторинг.

Расширение запрашивает доступ только к двум площадкам и локальному адресу приложения. Telegram-токен, cookies и содержимое остальных вкладок оно не передаёт приложению. Оно создаёт временные вкладки карточек и закрывает их после проверки, включая ошибки и таймауты. Существующие пользовательские вкладки не закрываются. Подробности: [docs/extension.md](docs/extension.md).

Крестик сворачивает основное окно в трей, если значок трея создан. Для полного завершения используйте «Выход». Автозапуск включается в настройках и работает после входа пользователя в Windows. Выключение, сон и выход из Windows останавливают мониторинг.

## Управление через Telegram

1. Сохраните токен в приложении. Откройте своего бота в личном чате и отправьте `/id` (после первого запуска подождите несколько секунд).
2. Введите полученный положительный ID в «Настройки → Ваш ID для ЛС», сохраните. ID группы остаётся отдельным отрицательным числом.
3. Отправьте `/start` и `/help`. Только этот пользователь в личном чате может управлять программой. Версия 0.4.1 автоматически обновляет нижнюю клавиатуру и меню команд этого чата: статус, разовый обход, запуск/остановка, товары, теги, добавление и удаление. Кнопки добавления открывают подсказки с командами.

Основные команды: `/status`, `/run`, `/stop`, `/products`, `/check all`, `/interval 60`, `/parallel 4`.
Добавление: `/add #arton https://www.ozon.ru/product/196525150/`.
Удаление: `/delete 12`, затем `/delete 12 confirm` (12 — ID строки в программе, не артикул).

Ошибки цен, ручная проверка, потеря связи с расширением и проблемы доставки в группу приходят сводкой в ЛС. Новые проблемы — не чаще раза в минуту; повтор той же сводки — раз в 30 минут. Подробности и полный список команд: [docs/telegram.md](docs/telegram.md).

Для работы нужны запущенное приложение и связь с Telegram. Выключенное приложение или потеря Интернета не позволяют отправить сообщение об этом через того же бота.

## Теги и разовая проверка всех цен

«Теги и пороги → + Добавить тег» создаёт свой тег с порогом в рублях. Имя можно вводить без `#`; оно сохраняется в нижнем регистре. Допустимы буквы, цифры, дефис и подчёркивание, до 50 символов. Новый тег доступен при добавлении и редактировании товаров.

Кнопка **«Проверить все сейчас»** на вкладке товаров разово проверяет все включённые карточки без ожидания их обычного интервала. Расписание не включается автоматически. Уже выполняющиеся проверки учитываются в этом обходе, повторные нажатия не создают копий заданий. Обход использует заданную параллельность, показывает число оставшихся карточек и переживает перезапуск. «Остановить» отменяет оставшийся обход. Товары на паузе пропускаются, HTTP 429 и ограничения доступа остаются в силе; при такой паузе часть обхода будет ждать её окончания.

Если автоматический мониторинг выключен, разовый обход обновляет цены, а рассылка ценовых событий в группу остаётся на паузе. Личные сообщения о проблемах продолжают работать. Из Telegram: `/tag #montana 400` и `/scan`.

## Скорость и большой список

Нет прежней задержки до 45 секунд и паузы между карточками. Свободный слот сразу получает следующий товар. Для одного товара существует только одно активное задание; пропущенные интервалы не создают копии заданий. Проверки распределяются между всем списком, включая непрерывный режим.

Интервал — пауза после завершения проверки товара, а не обещание обработать весь список за это время. При 200 товарах, средней проверке 4 секунды и 8 слотах один обход занимает примерно 100 секунд без учёта ограничений площадок. Это расчёт, а не измерение живых карточек. При превышении пропускной способности остаются ожидающие товары. Ограничения HTTP 429 и паузы после ошибок действуют отдельно от выбранного интервала.

Приложение и расширение нужно обновить до **0.4.2** вместе. По уточнению пользователя WB теперь отслеживается **с WB Кошельком** (261 ₽ на присланном примере), Ozon — по карте. Расширение понимает новую разметку `priceBlockWalletPrice-…`, а диагностика читает текущим кодом даже ранее открытую вкладку. Неизвестный ответ больше не выводится как `undefined`; отсутствие локального приложения объясняется отдельным сообщением.

Перед первым переходом на новый тип цены WB создаётся backup. Товары, пороги и история остаются, прежняя текущая цена WB очищается, отменяются ожидающие события старого типа, затем выполняется новое чтение. Цена без Кошелька не считается падением цены с Кошельком. Ozon не меняется. Расширению нужен Chrome/Edge 120+.

## Правила и хранение

- Локальная SQLite-база, история изменений, 16 тегов исходного задания, поиск, фильтр площадки, пауза и редактирование.
- Используется сессия обычного Chrome/Edge с установленным расширением. Приложение по умолчанию не запускает управляемый браузер.
- Ozon: `webPrice.cardPrice` или видимая цена с явной подписью Ozon Карты. Обычная цена не подставляется. WB: только видимая цена с WB Кошельком, подтверждённая ролью `priceBlockWalletPrice-…`, `.price-block__wallet-price` или явной подписью; обычная цена и JSON `price.product` не подставляются; неоднозначная цена остаётся неизвестной.
- Строгое условие `цена < порог`. Первая подтверждённая цена ниже порога создаёт событие. Затем новое уведомление приходит при дальнейшем снижении минимум на 15 ₽ от цены последнего успешно отправленного сообщения; мелкие шаги складываются. Например: 350 ₽ → 349 ₽ → 340 ₽ — без повтора; 335 ₽ — повтор. Подъём цены, остающейся ниже порога, эту отметку не сбрасывает. Подъём до порога или выше и новое пересечение вниз создают новое первое событие. Ошибки сохраняют последнюю достоверную цену.
- Изменение порога пересчитывает состояние без рассылки, задаёт новую исходную отметку по текущей цене и отменяет ожидающие события прежнего правила. Индивидуальные пороги не меняются при редактировании тега.
- Очередь переживает перезапуск. Потерянный ответ отправки помечается «Результат неизвестен»: сначала проверьте номер события в группе, затем подтвердите повтор вручную. Telegram не предоставляет идемпотентный ключ `sendMessage`.
- В Windows токен защищён DPAPI для текущего пользователя. Есть суточный SQLite backup (14 копий), ручной backup, блокировка второго экземпляра, автозапуск и трей.

Данные: `%LOCALAPPDATA%\PaintWatch`, отдельно от EXE. SQLite backup не содержит браузерный профиль или защищённый токен. Не публикуйте папку данных.

## Состояние проверок

Пользователь подтвердил, что обе карточки открываются в обычном Chrome его VM, а управляемый браузер ограничивается площадками. Версия 0.3 использует расширение. Автоматические тесты используют синтетические ответы и не доказывают реальную работу расширения на этих карточках: это ещё нужно проверить после его установки на VM.

CAPTCHA и ограничения не обходятся автоматически. Браузер остаётся для ручной проверки; отсутствие достоверной цены не заменяется старой или выдуманной ценой. Прохождение CAPTCHA не гарантирует доступ к API. Яндекс Маркет исключён.

Установка, восстановление и проверки: [docs/windows.md](docs/windows.md).

## Разработка

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-dev.lock
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/ruff check .
.venv/bin/ruff format --check .
node --test extension/tests/extractor.test.cjs extension/tests/background.test.cjs extension/tests/content.test.cjs extension/tests/popup.test.cjs
```

В Windows замените `.venv/bin/` на `.venv\Scripts\`. `build.ps1` собирает Windows x64 на Windows; EXE из Linux не кросс-компилируется. GitHub Actions проверяет ядро на Linux/Windows, окно и DPAPI на Windows, затем упакованный EXE. Работайте в существующем checkout; отдельный worktree не требуется.
