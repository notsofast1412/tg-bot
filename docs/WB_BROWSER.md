# Получение цен из обычного Chrome

На домашней VM ручной Chrome открывает WB, однако HTTPX возвращает 403 даже
с точными параметрами рабочего запроса. Отдельный `fetch` в открытой вкладке
тоже получил 403. Playwright, подключение через CDP и открытие URL при старте
Chrome с CDP получили 498. Причина различия пока не установлена.

Новый путь читает ответы, которые уже получила сама страница в обычном Chrome.
Расширение использует штатный `chrome.devtools.network.onRequestFinished` и
`getContent`. Удалённый отладочный порт, Playwright, инъекции скриптов в WB,
подмена свойств браузера, повторные запросы к WB и экспорт cookies не нужны.
Переход к следующей карточке выполняет `chrome.tabs.update`.
Для уже открытой карточки используется явный `chrome.tabs.reload`, чтобы новое
задание вызвало загрузку, а не повторную установку того же URL.

Расширение требует открытых DevTools. Владелец подтвердил работу на домашней VM:
ревизия расширения 2, товар 518397236, size 716573024, price_kopecks=26300,
warning=null. Это реальная проверка CLI; добавление и последующая проверка
через Telegram ещё требуют подтверждения на сервере.

## Установка на существующий Ubuntu-сервер

Нужны установленный Google Chrome, Xvfb, xauth, x11vnc и существующий
`var/vnc.pass`. Закройте прежний ручной браузер через Ctrl+C. После установки
нового кода выполните от root:

```bash
cd /opt/paintbot
runuser -u paintbot -- bash scripts/install.sh
bash scripts/setup_wb_browser.sh
```

Скрипт сохраняет существующий локальный ключ при повторном запуске, подготавливает
приватную копию расширения в `var/wb-extension` и запускает
`paintbot-browser.service`. Секреты Telegram этой службе не передаются.
Для обновления архива целиком есть `scripts/update_wb_browser.sh COMMIT_SHA`:
он создаёт backup настроек/базы/кода и обновляет службы, сохраняя `.env` и `var`.
При ошибке после остановки службы не запускаются поверх неполной установки;
путь резервной копии выводится в терминал.

## Однократная настройка Chrome

1. Подключитесь через прежний SSH-туннель к TigerVNC `127.0.0.1::15901`.
2. В Chrome откройте отдельную вкладку `chrome://extensions`.
3. Включите «Режим разработчика» → «Загрузить распакованное расширение».
4. Выберите каталог `/opt/paintbot/var/wb-extension`.
5. Закройте вкладку расширений, вернитесь на карточку WB. Закройте и снова
   откройте DevTools клавишей F12. В DevTools выберите Network.
6. Оставьте Chrome и DevTools открытыми. Окно VNC и SSH-туннель можно закрыть:
   служба продолжит работать.

После изменения файлов расширения нажмите его кнопку обновления на
`chrome://extensions`, затем закройте и откройте DevTools. При обычной перезагрузке
служба открывает DevTools автоматически; расширение сохраняется в том же профиле.

## Проверка до использования в боте

```bash
cd /opt/paintbot
runuser -u paintbot -- .venv/bin/python -m scripts.check_wb_browser
```

Нужны `Extension connected: True`, точный артикул/size и актуальная
`price_kopecks`. При первоначальной ручной проверке было 26300 копеек обычной
цены; 255 ₽ относились к кошельку и не используются. Цена могла измениться.
После настройки перезапустите `paintbot.service` и добавьте ссылку в Telegram.
Наличие `var/wb-browser.key` включает браузерный источник вместо старого API v2.
Если настроенный источник недоступен, прямой API не вызывается автоматически.

## Устройство и ограничения

Мост слушает только `127.0.0.1:8765`. Каждый запрос требует случайный локальный
ключ, не доступный странице WB; он хранится с правами 600. Ключ генерируется
локально и не должен попадать в чат. Из HTTP-заголовков WB читается только Age,
из query — ID товара и регион dest. Передаются только название, ID,
варианты, product-цена и численные остатки; сырые ответы, headers, cookies,
payload и account-поля не отправляются мосту и не записываются в журнал.

На один запрос создаётся одно задание сроком 75 секунд. Старые ответы, ответы
другой карточки, поздние результаты отменённого задания, чужой источник и Age
старше 120 секунд отвергаются. Цена берётся только из `price.product`
подтверждённого варианта с остатком. Несогласованные ответы оставляют цену
неизвестной. 429 устанавливает паузу минимум 600 секунд. База и миграции прежние.

Если расширение не подключено, появится понятная ошибка настройки, а не запрос
к старому API. Если сама страница получает 403/498, результат также считается
ошибкой; расширение не решает CAPTCHA. Проверьте карточку в этом же VNC-сеансе.

Служба браузера использует тот же сохранённый профиль, что ручной запуск.
Одновременно запускать второй Chrome с этим профилем нельзя. Для ручного запуска
сначала остановите `paintbot-browser.service`. Чтобы временно вернуться к старому
HTTP-источнику, остановите обе службы, переместите `var/wb-browser.key` в защищённую
резервную копию и запустите только `paintbot.service`; старый источник ранее
отвечал 403.

## Соединение есть, но цена не пришла

В выводе проверки должна быть `Extension revision: 2`. Старая копия расширения
не получает новых заданий: обновите её на `chrome://extensions`, затем закройте
и откройте DevTools на вкладке WB.

При ошибке CLI выводит `Browser trace`. Этапы показывают получение задания,
запрос перехода/перезагрузки, событие навигации, HTTP-статус документа и API,
чтение тела, отбрасывание кэша, проверку товара и приём результата. Эта диагностика
содержит только заранее определённые коды и численный статус: query, cookies,
ключ, headers и сырые ответы в неё не попадают. Последние этапы сохраняются
только в памяти службы. После изменения повторного перехода на reload владелец
получил реальную цену на VM. Это подтверждает результат новой версии, но само
по себе не изолирует единственную причину прежнего тайм-аута.
