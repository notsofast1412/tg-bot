# Источники, правила цены и ограничения

Единый интерфейс: `await adapter.fetch(CardRef) -> Card`. `price` — целое число
копеек либо `None`; `source` описывает метод/условия; `warning` — причину отсутствия
цены. Ошибки доступа/идентификации дают `MarketError`, никогда фиктивную цену.

## WildberriesAdapter

Chrome открывает точную карточку с выбранным `size`; Playwright читает только
ответ самой страницы `/__internal/u-card/cards/v4/detail` с HTTP 200. Прямые
запросы к старому `card.wb.ru` и HTML-резерв для WB удалены. Worker находится
в отдельном `.browser-probe`; бот запускает его через Xvfb и ограничивает время
жизни. Профиль `var/manual-browser-stable-profile` сохраняется. При ручном запуске
браузера с этим профилем мониторинг может получить ошибку занятости: остановите
VNC-браузер перед проверкой ботом.

Адаптер проверяет итоговую страницу, `id`, ровно один `chrtId`/`optionId` для
выбранного `size` и положительный остаток варианта. Общее `totalQuantity`
используется только у карточки с единственным вариантом. `price.product` хранится
в копейках; `basic`, цена кошелька и рекомендации не подставляются. Если получены
противоречивые снимки цены/наличия, цена остаётся неизвестной. Свежая проверка
в мониторинге выполняется отдельно от предпросмотра при добавлении.

Регион определяется сохранённым профилем браузера. Условия покупки, цена кошелька,
скидки аккаунта и доставка могут отличаться от `price.product`; регион не зашит
в URL API. Браузер на VM подтвердил 263 ₽ для 518397236/716573024 на момент проверки.
Sandbox, TLS и обычные свойства браузера сохраняются. CAPTCHA/401/403/429 не
обходятся; ошибка сохраняет прежнюю цену. HTTP 429 устанавливает паузу площадки.
При таймауте/отмене worker завершается вместе со своими дочерними процессами.
Браузер пишет только в `var`, в том числе при `ProtectSystem=strict` у systemd.

## OzonAdapter

HTTP GET прямой карточки, разбор `script[type=application/ld+json]`, включая
`@graph`. Ровно один Product с явным URL или sku/productID, совпадающим с ID
карточки. Другой URL исключает Product даже при совпавшем sku; общий canonical
не подтверждает цену из рекомендаций.

Цена допустима только для одного `Offer` в `RUB`, `availability=InStock`, с
положительным `price` и неистёкшим `priceValidUntil` (если задан). `AggregateOffer`,
диапазоны, несколько предложений, старая/неподтверждённая валюта не принимаются.
Ссылка Offer, если есть, тоже должна совпадать. HTML с CAPTCHA/страницей ограничения
не обходится. JS-only страницы, не содержащие достоверного JSON-LD, в этой версии
не поддерживаются. Для Ozon браузерный источник не подключён. Ozon JSON-LD реально проверен на карточке 196525011 (797 ₽).
Получение цен для других карточек пока не подтверждено.

## Безопасность и частота

Пользовательские URL допускаются только с точными разрешёнными hostnames и
известным форматом карточки. Запрещены логин/пароль, порты и произвольные хосты.
Используется HTTPS; TLS проверяется. Для HTTP-адаптера Ozon — не более трёх перенаправлений при загрузке
карточки, каждое должно сохранять площадку и полный идентификатор карточки/
варианта. Адрес назначения проверяется до сетевого запроса; смена товара,
неизвестный хост, порт, userinfo, HTTP downgrade, страница авторизации и циклы
отклоняются. Это позволяет обычный переход Ozon на ту же карточку с `__rr=1`.
Короткие ссылки Ozon `/t/<код>` раскрываются отдельно (до трёх запросов),
только в прямую карточку Ozon. Другие сокращатели не поддерживаются.
Tracking query отбрасывается, значимые поддержанные селекторы сохраняются.

Интервал проверки 600 с или больше; между HTTP-запросами одной площадки ≥5 с
по умолчанию; фактическая пауза случайно выбирается от базовой до 1,5 базовой,
один сетевой запрос одновременно. Две попытки максимум при сетевых
ошибках/5xx; после ошибки exponential backoff до 6 ч. HTTP 429 учитывает
`Retry-After` (до 24 ч), сохраняет паузу площадки в БД и не блокирует остальные
адаптеры. Ошибки не удаляют последнюю достоверную цену и её время. Ответы с
`Age > 120` не используются как актуальные. Другие непрозрачные серверные кэши
невозможно полностью обнаружить: успешный fetch означает наблюдение ответа
сервера в данный момент, а не гарантию отсутствия кэша на стороне площадки.

Не обходятся CAPTCHA, авторизация, платные ограничения и иные механизмы защиты.
Перед эксплуатацией проверьте правила каждой площадки и разрешённую частоту.
Если требуется более редкая проверка, увеличьте `CHECK_INTERVAL_SECONDS`; бот
показывает фактический базовый интервал и время следующей попытки товара.

## Честная граница гарантий уведомлений

Один переход создаёт одну запись очереди с UNIQUE `(product_id, generation)` в
той же транзакции, что цена/состояние/история. Повторная обработка не создаёт
второго логического события. Успешная доставка хранит `message_id`.

Telegram Bot API `sendMessage` не поддерживает клиентский idempotency key.
После timeout/5xx либо аварии между отправкой и фиксацией ответа нельзя узнать,
доставлено ли сообщение. Гарантировать одновременно автоматическую доставку
без потерь и отсутствие физических дубликатов невозможно. Поэтому такие записи
становятся `uncertain`, видны в `/queue`, не отправляются автоматически повторно.
Владелец проверяет группу и подтверждает `/retry ID`, понимая риск дубликата.
Подтверждённое ограничение 429 повторяется автоматически (не больше 8 попыток),
ошибки прав/ID требуют исправления и ручного возврата в очередь. Пока группа не
настроена, события остаются `pending`.

Это явное ограничение относительно требования о полностью автоматических
повторах при любых сбоях Telegram. Оно не скрывается за тестами с моками.
