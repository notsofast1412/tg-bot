# Установка на Ubuntu 22.04

Нужны SSH-доступ и sudo. Команды ниже предназначены для первой установки. Если `/opt/paintwatch` уже существует, остановитесь и используйте порядок обновления с backup из [эксплуатации](operations.md).

## 1. Подключение к серверу

В терминале **своего компьютера** выполните, заменив `USER`, `SERVER` и порт `22` своими значениями:

```bash
ssh -p 22 USER@SERVER
```

Пароль SSH вводится только в терминале, когда его запросит SSH. Токен бота и приватный SSH-ключ в чат не отправляйте.

Остальные команды выполняются **на сервере**. Сначала проверьте ОС:

```bash
cat /etc/os-release
```

## 2. Python 3.12

В Ubuntu 22.04 штатный Python 3.10; проект требует 3.12. Ниже подключается дополнительный репозиторий [deadsnakes PPA](https://launchpad.net/~deadsnakes/+archive/ubuntu/ppa), который поставляет отдельные пакеты Python. Это сторонний репозиторий, он останется подключённым для обновлений этих пакетов. Проверка подписей apt сохраняется. Системный `/usr/bin/python3` не меняйте.

```bash
sudo apt-get update
sudo apt-get install -y git software-properties-common ca-certificates
sudo add-apt-repository -y ppa:deadsnakes/ppa
sudo apt-get update
sudo apt-get install -y python3.12 python3.12-venv
python3.12 --version
```

При недоступности PPA остановитесь и сохраните текст ошибки; не отключайте проверку подписей или TLS.

## 3. Файлы и служба

Клонируйте `main` из GitHub. Если каталог установки уже существует, сначала проверьте его содержимое и сделайте backup: не удаляйте его ради повторного клонирования. Если репозиторий закрытый, используйте настроенный на сервере GitHub-доступ; пароль аккаунта GitHub для HTTPS Git не подходит. Токены доступа не вставляйте в URL или сообщения чата.

```bash
sudo git clone --branch main --single-branch https://github.com/notsofast1412/tg-bot.git /opt/paintwatch
cd /opt/paintwatch
sudo bash scripts/install.sh
sudoedit /opt/paintwatch/.env
```

В редакторе заполните:

```dotenv
BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
OWNER_ID=ВАШ_ЧИСЛОВОЙ_TELEGRAM_ID
NOTIFICATION_CHAT_ID=-1001234567890
```

Подставьте настоящие значения только в файл на сервере. `OWNER_ID` — положительное число, не username и не ID группы. `NOTIFICATION_CHAT_ID` — числовой ID вашей группы, пример выше нужно заменить; эту строку можно пока пропустить и позже выполнить `/setgroup` в личном чате бота. Остальные настройки оставьте по умолчанию, включая `BROWSER_ENABLED=false`.

Установщик создаёт пользователя службы, venv и SQLite, проверяет хеши зависимостей, устанавливает systemd unit. Существующий `.env` сохраняется. Он не запускает бота до заполнения настроек.

```bash
sudo -u paintwatch .venv/bin/python -m paintwatch.cli doctor
sudo systemctl enable --now paintwatch
sudo systemctl status paintwatch --no-pager
sudo journalctl -u paintwatch -n 50 --no-pager
```

`doctor` проверяет локальные настройки, но не доставку сообщений. Служба должна показать `active (running)` и отвечать на `/start` владельцу. Бот использует long polling: открывать входящие порты, ставить nginx или покупать домен не нужно. Требуется исходящий HTTPS к Telegram, Ozon и Wildberries, а при установке — к репозиториям apt и PyPI.

## 4. Уведомления в группу и проверка товаров

1. Добавьте бота в нужную группу и разрешите отправлять сообщения.
2. Напишите боту `/start` в личном чате с аккаунта владельца.
3. Если группа не задана в `.env`, отправьте в личном чате `/setgroup -100…` с настоящим числовым ID. Настройка группы в базе имеет приоритет над `.env`.
4. Нажмите «🔌 Диагностика», затем «📨 Проверить отправку в группу». Убедитесь, что тестовое сообщение действительно появилось в нужной группе.
5. Добавьте ссылки на товары, выберите тег и порог. Проверяйте отображаемую цену и статус. Ozon отслеживается по цене по карте.

Для отдельной проверки источников из `/opt/paintwatch`:

```bash
sudo -u paintwatch .venv/bin/python -m paintwatch.cli probe 'https://www.ozon.ru/product/196525150/'
sudo -u paintwatch .venv/bin/python -m paintwatch.cli probe 'https://www.wildberries.ru/catalog/29220564/detail.aspx'
```

Код выхода `2` означает, что цена не подтверждена; текст результата объясняет причину. В облачной среде WB отвечал 403/498. Новый сервер может дать другой результат, но перенос сам по себе не гарантирует доступ WB. Отказ WB не останавливает Ozon и Telegram.

При проблеме пришлите текст ошибки или последние строки журнала после удаления секретов. Сам `.env` присылать не нужно. Не запускайте второй экземпляр бота вручную рядом со службой. Для перезапуска после изменения `.env`: `sudo systemctl restart paintwatch`.

Эти команды подготовлены для Ubuntu 22.04; фактическая установка и проверка systemd на вашем сервере ещё не выполнены.
