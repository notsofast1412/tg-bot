# Перенос на сервер через работающий SSH с Windows

Для домашней Ubuntu 22.04 используется обычный доступ в интернет. Для
Telegram long polling не требуется проброс входящих портов на роутере.
Команды выполняет владелец через свой терминал, без передачи паролей в чат.

## 1. Перенос архива

Скачайте актуальный `tgbot-source.tar.gz` из чата в Downloads. Откройте **отдельное
локальное окно PowerShell**, не серверную SSH-консоль:

```powershell
scp "$env:USERPROFILE\Downloads\tgbot-source.tar.gz" root@201.51.22.210:/root/tgbot-source.tar.gz
```

Если файл сохранён под другим именем/в другой папке, исправьте локальный путь.
Пароль SSH вводите только в PowerShell, не в переписке.

## 2. Первичная установка в серверном SSH-окне

Это новый каталог и новая учётная запись `paintbot`. Если они уже существуют,
остановитесь и используйте процедуру обновления: данные не перезаписываются.

```bash
if [ -e /opt/paintbot ]; then
  echo 'Каталог /opt/paintbot уже существует — требуется проверка перед обновлением'
else
  mkdir -m 750 /opt/paintbot &&
  tar -xzf /root/tgbot-source.tar.gz -C /opt/paintbot --strip-components=1 &&
  bash /opt/paintbot/scripts/bootstrap_ubuntu.sh
fi
```

Установщик ставит только `python3-venv` и CA-сертификаты через apt, создаёт
системного пользователя и отдельный Python **3.12.14** через **uv 0.12.23**.
Системный Python не меняется. Этот выбор избегает совместимости старых
зафиксированных бинарных зависимостей с новым Python Ubuntu 26.04.
uv устанавливается из PyPI, Python — из каталога python-build-standalone через
uv с обычной проверкой целостности/TLS. Проверки не отключаются.

Применяются зависимости, миграции, теги; запускаются тесты. Копируются только
три units Paint Monitor. Бот и timer пока не включаются. Firewall, SSH и маршруты не настраиваются. Требуется исходящий HTTPS к Ubuntu archive,
PyPI и GitHub release assets. При ошибке сохраните текст ошибки без секретов.

## 3. Защищённая локальная конфигурация

```bash
cd /opt/paintbot
runuser -u paintbot -- .venv/bin/python -m scripts.configure
```

Введите токен BotFather: ввод скрыт. Затем числовой Telegram ID владельца и
необязательный отрицательный ID группы. Это реальный Telegram ID человека,
не username и не ID бота. Если группа неизвестна, оставьте пустой и настройте
позднее в личном чате бота. `.env` получает права 600; токен не выводится.
Существующие прочие настройки и прежний GROUP_ID при пустом вводе сохраняются.
Если защищённый интерактивный терминал недоступен, конфигуратор остановится,
а не перейдёт к открытому вводу токена.

## 4. Фактическая проверка с сервера

```bash
runuser -u paintbot -- .venv/bin/python -m scripts.verify_server
```

Команда запрашивает две ссылки WB/Ozon, проверяет Telegram getMe,
webhook и членство/права группы (если она задана). Тестовое сообщение не
отправляется без отдельного флага:

```bash
runuser -u paintbot -- .venv/bin/python -m scripts.verify_server --send-test
```

Это явно разрешённая тестовая отправка только в настроенную группу. Цена,
история и очередь мониторинга не меняются. Ненулевой код означает, что какая-то
проверка неуспешна; не считать его успешным запуском всех интеграций. CAPTCHA,
403 и неоднозначные цены не обходятся. Код возврата 0 без группы подтверждает
доступ к API бота, но не доставку в группу.

## 5. Постоянный запуск

После успешной проверки токена и осознанного рассмотрения ошибок площадок:

```bash
systemctl enable --now paintbot.service paintbot-backup.timer
systemctl status paintbot.service --no-pager
journalctl -u paintbot.service -n 60 --no-pager
```

В Telegram откройте личный чат: `/start`, затем `/setgroup` при необходимости,
«Диагностика» и «Проверить отправку в группу». Ссылки из диагностики не
добавляются в мониторинг автоматически: добавьте их через подтверждённый
сценарий с выбранным тегом/порогом.

## Границы проверки

Доступные проверки в облаке относятся к Python 3.12 и мокам/отдельным живым
запросам. Установщик Ubuntu 26.04, apt, systemd и сеть конкретного сервера
не проверены удалённым исполнением: SSH из облака пока недоступен.
Текущие фактические результаты фиксируются после выполнения владельцем этих
команд. Токены, ключи и полный `.env` для диагностики в чат не присылайте.
