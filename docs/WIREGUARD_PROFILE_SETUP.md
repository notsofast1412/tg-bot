# Готовый WireGuard-профиль, российский Endpoint 95.161.4.67

Владелец сообщил, что имеет только профиль WireGuard от сервиса, без SSH к
российскому узлу. Подготовлена установка на его европейский Ubuntu-сервер
201.51.22.210. Агент не устанавливает VPN в своём облачном контейнере.

## Схема

На европейском сервере создаются:

- отдельный network namespace `paintbot-ru`;
- WireGuard-интерфейс `pbru-wg` внутри него, с UDP-сокетом в исходном namespace;
- приватная veth-пара из свободной подсети, выбранной после чтения маршрутов;
- небольшой собственный HTTPS CONNECT relay на Python stdlib, без Squid,
  дополнительных Python-зависимостей и публичного proxy-порта.

Default route через WireGuard добавляется **только внутри нового namespace**.
Нет изменения default route хоста, SSH, firewall, IP forwarding или NAT.
DNS для proxy тоже работает внутри namespace: используются IPv4 DNS профиля,
отдельные resolv.conf/nsswitch.conf без обращения к host systemd-resolved.
IPv6 default route не создаётся; outbound proxy использует AF_INET.

Relay привязан к приватному veth-адресу, принимает соединения только от адреса
его хостовой стороны, разрешает только CONNECT/443 к `card.wb.ru`,
`www.wildberries.ru`, `ozon.ru`, `www.ozon.ru`. Он передаёт зашифрованные байты,
не расшифровывает TLS, не подменяет сертификаты, не кэширует цены. Число туннелей,
размер заголовков и тайм-ауты ограничены. Telegram и Яндекс его не используют.

При падении VPN новый namespace не имеет другого интернет-маршрута. В боте
настроенный proxy тоже не заменяется прямым соединением. Поэтому случайный
простой VPN не переключает мониторинг обратно на европейский выход.

## Требования

- Бот уже установлен в `/opt/paintbot` из **актуального архива**, существует
  пользователь `paintbot` и файл `.env`; токен можно ввести позднее.
- Root на реальном Ubuntu с systemd и поддержкой WireGuard/network namespace.
  Если VPS-провайдер запрещает необходимые kernel capabilities, установка
  остановится; потребуется разрешённый провайдером способ VPN.
- Стандартный профиль с одним Interface и одним Peer, IPv4 Address и DNS,
  разрешением полного IPv4 внутри туннеля, MTU 576–1420.
- Endpoint профиля должен совпадать с `95.161.4.67` (порт читается из профиля,
  не предполагается). DNS-имя Endpoint допускается, если оно разрешается в этот IP.
- AmneziaWG и исполняемые PreUp/PostUp/PreDown/PostDown hooks не поддерживаются
  и не запускаются. При обнаружении нестандартных полей установщик остановится.

## Передача профиля — только непосредственно на сервер

В **локальном PowerShell** Windows, не в серверной SSH-консоли, выполните:

```powershell
scp "C:\ПУТЬ\К\ВАШЕМУ\wg-russia.conf" root@201.51.22.210:/root/wg-russia.conf
```

Замените путь на настоящий. В профиль входят приватные ключи: не отправляйте
его в чат, не размещайте в `/opt/paintbot` и не добавляйте в Git/архив проекта.
Пароль SSH вводите в собственном терминале. Если новый архив ещё не перенесён,
сначала выполните начальную установку из SERVER_DEPLOYMENT.md.

## Установка в SSH-консоли европейского сервера

```bash
chmod 600 /root/wg-russia.conf
cd /opt/paintbot
bash scripts/setup_ru_vpn.sh /root/wg-russia.conf
```

Установщик проверяет, что конфигурации/units с этими именами ещё нет. Ставит
`wireguard-tools`, `iproute2`, `python3`, `curl`, `ca-certificates` из apt.
Копирует root-owned runtime helper в `/usr/local/libexec`, а ключи — в root-only
`/etc/paintbot-ru` с правами 600. Профиль не печатается и не исполняется как shell.
Units создаются отдельно от основного бота.

Перед изменением proxy-настроек бота выполняются три реальные проверки:

1. HTTPS к присланной карточке Ozon через relay с обычной проверкой TLS;
2. свежий WireGuard handshake;
3. IPv4 выхода через HTTPS `api.ipify.org` из namespace, без передачи ключей или
   токена. Он должен быть **95.161.4.67**.

Если VPN-сервис использует другой публичный exit IP, даже при таком Endpoint,
установщик покажет фактический IP и остановится до изменения `.env`. Это не
доказательство неработающего VPN: нужно уточнить разрешённый выходной адрес у
провайдера. Сама география IP не определяется этим тестом и не гарантируется.

При провале любой проверки прежние WB_PROXY_URL/OZON_PROXY_URL сохраняются.
Если всё прошло, изменяются только эти две строки `.env`, остальные настройки
и токен сохраняются. Units включаются на автозапуск; уже работающий бот
перезапускается для применения proxy. Не запущенный бот автоматически не стартует.

HTTPS-ответ Ozon 403/редирект может подтвердить транспорт, но не цену:
актуальные цены и Telegram проверяются отдельно:

```bash
cd /opt/paintbot
runuser -u paintbot -- .venv/bin/python -m scripts.verify_server
```

Для конфигурации токена используйте `scripts.configure`, как в SERVER_DEPLOYMENT.md.
Не присылайте вывод полного `.env`, `wg showconf` или содержимое исходного профиля.

## Статус и неисправности

```bash
systemctl status paintbot-ru-netns.service paintbot-ru-proxy.service --no-pager
ip netns exec paintbot-ru wg show pbru-wg latest-handshakes
journalctl -u paintbot-ru-netns -u paintbot-ru-proxy -n 60 --no-pager
```

`latest-handshakes` не содержит private key; перед отправкой журналов убедитесь,
что они не содержат вручную добавленных секретов. Нулевой timestamp означает,
что handshake не состоялся. Проверяйте корректность профиля, UDP-доступ к Endpoint,
срок действия VPN и поддержку WireGuard у VPS-провайдера. CAPTCHA, 401/403 и
ограничения частоты маркетплейсов не обходятся сменой/ротацией адресов.

Если первичная установка не прошла после создания units, не запускайте установщик
повторно вслепую: он намеренно не перезаписывает созданную конфигурацию. Исправление
внешнего UDP-доступа/активации профиля может не требовать её замены; units можно
перезапустить отдельно. Смена самого профиля требует остановки proxy/namespace,
сохранения старых настроек и отдельной процедуры обновления.

## Остановка и осознанный откат

Остановить VPN, оставив приложениям запрет на прямой fallback:

```bash
systemctl disable --now paintbot-ru-proxy.service paintbot-ru-netns.service
```

Это не удаляет proxy-настройки приложения: проверки будут показывать ошибки.
Для **намеренного возврата к прежнему маршруту** восстановите сохранённые две
строки (остальной `.env`, включая токен, остаётся текущим), затем перезапустите бот:

```bash
python3 -I /usr/local/libexec/paintbot-ru-vpn.py detach
systemctl restart paintbot.service
```

Root-only предыдущие proxy-строки хранятся в `/etc/paintbot-ru/previous-proxy-lines.json`.
Не удаляйте этот файл перед откатом. Удалять ключи/профиль нужно отдельно и только
после остановки соответствующих служб.

## Проверено и не проверено

В облаке проверены разбор синтетических профилей, отклонение hooks/неверного
Endpoint/DNS, выбор свободной подсети, команды маршрутизации с моками, HTTP CONNECT
ACL и реальная передача непрозрачных байтов через локальный TCP relay, ошибки
upstream, shell syntax и статическая проверка units. Эти проверки не создают
WireGuard или namespace в контейнере Codex. Подключения к 95.161.4.67 и фактического
российского выхода с VPS пока нет: приватный профиль находится у владельца.
