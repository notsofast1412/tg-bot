# Эксплуатация и восстановление

## Восстановление

1. Остановите службу: `sudo systemctl stop paintwatch`.
2. Проверьте путь к согласованной копии. `.env` не входит в SQLite backup и хранится отдельно безопасным способом.
3. Из `/opt/paintwatch` выполните от пользователя службы:

```bash
sudo -u paintwatch .venv/bin/python -m paintwatch.cli restore data/backups/paintwatch-XXXXXXXXXX.sqlite3
sudo -u paintwatch .venv/bin/python -m paintwatch.cli doctor
```

Команда проверяет целостность и основные таблицы, блокирует параллельный запуск, сохраняет текущую базу в `before-restore-*`, использует SQLite Backup API и применяет миграции. Не копируйте один `.sqlite3` поверх работающей базы: WAL-файлы могут содержать изменения.

4. Перед запуском учтите: старый backup не знает о сообщениях, отправленных после его создания. Проверьте последние события группы и очередь. Абсолютная защита от повторной доставки при откате внешнего состояния невозможна. Если нужно сверить спорную очередь до запуска, используйте SQLite read-only инструменты/изолированную копию без Telegram-токена; не редактируйте основной файл работающего приложения вручную.
5. Запустите службу: `sudo systemctl start paintwatch`, проверьте `/status`, `/queue` и тестовую отправку. Записи `sending` после аварии становятся `uncertain`; повторяются только по подтверждённому `/retry ID`.

## Типичные проблемы

| Признак | Что проверить |
|---|---|
| `BOT_TOKEN`/`OWNER_ID` не заданы | Заполните `.env` безопасным редактором, права 600, владелец `paintwatch`. `doctor` выводит только наличие. |
| Бот не отвечает | Пишите из личного чата нужного `OWNER_ID`. Команды в группе и от посторонних намеренно игнорируются. Проверьте журнал службы и webhook. |
| Тест не доставлен в группу | `/setgroup`, участие бота, права отправки, сеть. Кнопка показывает результат фактической попытки; при тайм-ауте проверьте группу перед повтором. |
| Очередь `blocked` | Исправьте права/ID группы. Сохранение `/setgroup` возвращает такие события в очередь; автоматически также повторяются через час. |
| Очередь `uncertain` | Ответ на `sendMessage` потерян. По номеру события проверьте группу; `/retry ID` потребует подтверждения риска повторной доставки. |
| HTTP 403/498, CAPTCHA | Ограничение доступа площадки. Не включайте stealth и не отключайте проверки TLS. Нужен допустимый доступ/источник или решение площадки; цена не подтверждена. |
| HTTP 429 | Увеличьте интервал и паузу запросов; сохранённый backoff не нужно сбрасывать частыми `/check`. |
| `no_price`/`browser_disabled` | Посмотрите причину: товар недоступен, неоднозначный вариант, нет цены по карте, изменилась структура. Включение браузера не гарантирует получение данных. |
| `seller_changed` | Не подтверждён исходный продавец. Перепроверьте конкретную карточку/вариант; другой продавец не отслеживается молча. |
| Цена в браузере отличается | Сравните тип цены, карту, купон, регион WB, выбранный вариант и время. Ozon мониторится по карте без личной сессии, условия оплаты могут отличаться. |
| Другой экземпляр уже работает | Не запускайте `python -m paintwatch.main` рядом с systemd на том же `DATA_DIR`. Один процесс обслуживает scheduler, Telegram и очередь. |
| Недостаточно места | Контролируйте `data/`, журналы попыток и backups. Удаление истории из базы выполняйте отдельно после backup и остановки службы. |

В Telegram не отправляются сырые HTTP-ответы, токены и пароли. Ошибки адаптеров изолированы: отказ WB не останавливает Ozon. Неожиданная остановка одного из фоновых компонентов завершает процесс, чтобы systemd перезапустил весь согласованный набор.
