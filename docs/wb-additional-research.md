# Дополнительный поиск способов чтения цен WB

Проверено 19.10.2026, МСК. Исследованы исходники трёх дополнительных проектов, публичные сообщения об отказах и копия схем Seller API. Чужой код не запускался, browser-session cookies и токены не получались и не переносились. Ниже разделены сведения из чужих исходников и фактическая проверка на этой машине.

## Новый кандидат API и результат запроса

В `TimNekk/MarketplacesGoodsTracker` на коммите `66ca370a67d993e54ef639ae3447cc84248718b5` от 28.08.2026 WB-адаптер использует:

```text
https://www.wildberries.ru/__internal/u-card/cards/v4/detail
```

Источник: [wildberries_parser.py](https://github.com/TimNekk/MarketplacesGoodsTracker/blob/66ca370a67d993e54ef639ae3447cc84248718b5/src/parsing/wildberries_parser.py). Это другой host/path, чем реализованный в PaintWatch `card.wb.ru/cards/v4/detail`. Тот же текущий frontend-адрес упоминается в независимом [issue region-price-monitor #60](https://github.com/persfinancier-blip/region-price-monitor/issues/60), где автор приводит наблюдения DevTools. Эти сведения делают адрес конкретным кандидатом для проверки, но не доказывают его общедоступность.

Выполнен **один обычный запрос** через унаследованный прокси среды: `nm=29220564`, `spp=30`, `dest=-1257786`, `curr=rub`, `appType=1`. Browser cookies, WBAAS-токен, подмена fingerprint и браузерных заголовков не использовались. Результат: **HTTP 403**, данные карточки не получены. Источник отказа по этому ответу не установлен. Последующих попыток преодолеть проверку не было.

Таким образом, замена URL на этот кандидат сама по себе не решила проблему в данной среде. Основной адаптер не объявлен исправленным; актуальная цена WB по-прежнему не подтверждена.

## Официальный Seller API

В публичной [копии OpenAPI Seller API](https://github.com/Gueriero/wb_wildberries_api_swagger), актуальной по README на 27.04.2026, изучен `GET /api/v2/list/goods/filter` на `discounts-prices-api.wildberries.ru`. Он требует `Authorization` (`HeaderApiKey`), а описание относится к товарам продавца. Поэтому его нельзя обещать как замену мониторинга произвольной чужой карточки `29220564`. Боевой запрос к Seller API не выполнялся, подходящий seller-token не предоставлен и не требуется запрашивать для неподтверждённого сценария.

## Ограничения текущей среды

Сопоставлены runtime-статус и `/etc/codex/network-policy.json`: политика при старте содержит package-manager presets, custom-домены WB/Ozon/Telegram остаются в черновике; текущий runtime сообщает сетевое состояние `unknown`. Это не доказательство того, что именно политика породила 403, но актуальная применённая конфигурация сети всё ещё не подтверждена. Обход штатного прокси не используется.

Обычный Chromium не может использовать существующий NSS-каталог из-за `SEC_ERROR_READ_ONLY`, как установлено в [предыдущем разборе](wb-investigation.md). Запись в него не разрешена. Новые сертификаты не нужны: нужный CA уже доверен. Перенос или повторный импорт доверия как обход ранее отклонённой операции не выполнялся.

Следующая содержательная проверка — обычный браузерный доступ после разрешённого исправления доступа к NSS и применения конфигурации среды. Она не гарантирует прохождение WBAAS, и не должна автоматически решать CAPTCHA/защиту. До получения свежего ответа с точным ID и ценой считать интеграцию WB работающей нельзя. Поисковая выдача, архивная цена и нулевая заглушка не используются вместо текущей цены.
