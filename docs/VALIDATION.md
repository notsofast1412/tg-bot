# Проверки текущей версии

Поддерживаются только WB и Ozon. Поддержка прокси и управления VPN удалена:
клиенты Telegram и маркетплейсов игнорируют прокси-переменные окружения,
проверяют TLS и используют системное хранилище доверенных сертификатов.
Старые поля WB_PROXY_URL и OZON_PROXY_URL в .env игнорируются.

Автотесты проверяют SQLite, мониторинг, Telegram, обработку карточек и отказов,
отключение товаров удалённых площадок с сохранением истории. Отдельный тест
выполняет реальные локальные HTTP-запросы клиентов WB/Ozon и Telegram при
заведомо непригодных прокси-переменных. Это проверяет выбор транспорта,
но не подтверждает доступ к внешним сервисам. Проверка TLS остаётся включённой.

На домашней Ubuntu 22.04 владелец подтвердил работу Telegram и HTTP 403 Ozon
для короткой ссылки hiu5Rnt и прямой карточки 197922669. В браузере компьютера
карточка доступна. Причина различия ответов ещё не установлена.

## Локальный мост обычного Chrome

Подготовлен отдельный источник через расширение Chrome DevTools. HTTPX и
Playwright не обращаются к WB в этом режиме: браузер загружает штатную страницу,
расширение передаёт только публичные поля ответа `/__internal/u-card/cards/v4/detail`.
Новый режим не проверен на домашней VM. Не утверждаем, что он устраняет 403/498:
для этого нужны подключённое расширение и подтверждённая актуальная цена.

Проверены реальный локальный HTTP-обмен, авторизация, одно активное задание,
отмена/таймаут, отбрасывание старых/чужих ответов, выбор optionId, остатки,
неоднозначные цены и пауза 429. JS-harness исполняет настоящий код расширения
с имитацией Chrome API: задание → переход вкладки → сетевое событие → getContent
→ фильтрация полей → локальный результат. Он не заменяет запуск в настоящем Chrome.
Схема БД и lockfile зависимостей не изменены.
Полный набор проверок этой реализации в облаке: 148 passed, без пропусков.
Проверен путь добавления → отдельное свежее наблюдение → история цен и очередь;
цена предпросмотра не используется как результат следующей проверки.
После подключения расширения владелец получил True, но проверка цены завершилась
тайм-аутом. Добавлена явная перезагрузка уже открытой карточки, проверка ревизии
расширения и этапы диагностики без секретов. JS-тест проверяет разные URL через
update и повторную карточку через reload. Это исправление пока не проверено на VM.

В облаке отсутствует `/usr/bin/xvfb-run`: `systemd-analyze verify` сообщает об
этом исполняемом файле. Поэтому запуск службы Chrome в облаке не проверен;
на домашней VM Xvfb и Chrome ранее работали. Python-часть установщика расширения
проверена дважды в изолированном каталоге: ключ сохраняется, приватные файлы
имеют права 600. Это не является проверкой загрузки расширения настоящим Chrome.
