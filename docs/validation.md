# Проверки расширения 0.4.8

Приложение остаётся версии 0.4.7. Пройдены 67 JavaScript-тестов и полный локальный Python-набор из 133 тестов: 129 пройдено, 4 графических пропущены без desktop-сеанса; в набор входят 21 браузерная фикстура Chromium. Ruff, форматирование и проверка пробелов пройдены. Windows CI конкретного коммита проверяет графический интерфейс, упаковку и запуск EXE.

Таймер проверен искусственными часами до и после границы 30 минут, включая повторный цикл и сохранение срока при перезапуске. Проверены закрытие личных/закреплённых вкладок в разных окнах и вкладки без доступного URL, сохранение одной лёгкой вкладки без повторного создания, отсутствие новых заданий во время завершения текущих проверок и возобновление после очистки. Текущие результаты передаются до массового закрытия, штатный таймаут даёт ровно один результат. Сохранённые в приложении активные задания задерживают очистку после перезапуска расширения.

Проверены отключённая автоочистка, ручная очистка при выключенном таймере, отказ неподключённого расширения, отсутствие автоматического запуска остановленного мониторинга, ошибка создания оставляемой вкладки, частичный отказ закрытия и потеря связи с приложением. При сбоях запрос остаётся ожидающим, новые задания не выдаются, повтор не закрывает последнюю вкладку. Запоздалое создание старой проверочной вкладки после очистки не оставляет лишнюю вкладку. Обычное закрытие проверочной вкладки распознаёт pendingUrl до завершения навигации.

Chrome API в тестах подменён; живое закрытие всех вкладок профиля здесь не выполнялось. Полная установка расширения в облачном Chromium ограничена политикой браузера. После обновления у пользователя нужно проверить кнопку «Очистить вкладки сейчас» и убедиться, что браузер остался открыт, а мониторинг продолжился. Функция включена по прямому запросу пользователя и явно подписана в popup: она затрагивает и личные вкладки. Новых разрешений и изменений схемы SQLite нет.

## История версии 0.4.7

Полный локальный набор: 133 Python-теста, 129 пройдено, 4 графических пропущены без desktop-сеанса; 53 JavaScript-теста пройдены. В Python входят 21 браузерная фикстура Chromium. Ruff, проверка форматирования и `git diff --check` пройдены. Графические проверки, PowerShell, упаковка и запуск готового EXE выполняются Windows CI конкретного коммита.

На 621 искусственном товаре проверен справедливый непрерывный обход с шестью слотами, включая результаты в одну секунду: все товары получают проверку, активные задания не дублируются. Проверены готовность очереди при паузе площадки и истёкших заданиях, статистика успешных/ошибочных/закончившихся товаров, длительность попыток и исключение данных старше пяти минут. Неизменившиеся 621 строки не вызывают операций изменения Tk; изменение одной строки обновляет только её. Проверены фильтрация и восстановление строк, пропуск периодического обновления скрытого окна, SQL-фильтр очереди уведомлений и ограничение записи heartbeat.

Chrome API в JavaScript подменён: проверены правила только для нужного ID вкладки, инициаторов площадок и типов image/media, ручная вкладка и выключенный флажок, очистка после смены URL, оставшиеся правила и позднее завершение установки правила после таймаута без повреждения следующего слота. Тысяча мутаций DOM объединяется в ограниченное число чтений; первая мутация и последняя цена перед дедлайном не теряются. В настоящем Chromium цена Ozon читается при отменённых запросах изображений. Полная установка расширения ограничена политикой облачного браузера, поэтому эта фикстура не подтверждает работу установленного declarativeNetRequest на живых сайтах.

Синтетическое сравнение 100 пустых опросов с 621 товаром, шестью слотами и будущими сроками: прежний путь выполнял 700 локальных HTTP-обращений и 5200 открытий SQLite, новый — 100 и 201 соответственно. Сравнение использует Bridge коммита 13d6e8b и текущий Store на одной временной базе. Это измерение служебной работы при отсутствии заданий; скорость живых карточек и снижение CPU/RAM Windows им не измерены. Их нужно проверить на пользовательской ВМ после обновления обеих частей до 0.4.7.

Схема SQLite остаётся версии 4; добавлен индекс очереди по состоянию и ID. Настройки интервала, параллельности и лимита обновление не меняет. Рекомендация для текущих 621 товара на 4 vCPU / 8 ГБ — начать с шести слотов, лимита 25 секунд и непрерывного интервала 0, затем оценить `/status` и загрузку ВМ. CAPTCHA и HTTP 429 сохраняют паузы; частота полного обхода не гарантируется.

## История версии 0.4.2

Локально в Linux/Python 3.12 с Chromium: 93 Python-теста, 89 пройдено, 4 графических пропущены без desktop-сеанса. 33 JavaScript-теста пройдены, включая новый набор popup. Ruff, форматирование, компиляция Python, синтаксис JavaScript и `git diff --check` пройдены.

По последнему уточнению пользователя WB теперь отслеживается с WB Кошельком, 261 ₽ на присланном примере. Проверено:

- фрагмент пользователя `span.mo-typography…priceBlockWalletPrice-E4q0H` с `261&nbsp;₽` распознаётся в Chromium даже без прежнего контейнера `.price-block`;

- обычная цена 270 ₽, зачёркнутая 379 ₽, один красный цвет без роли, скрытая/зачёркнутая/неоднозначная цена Кошелька не подставляются;
- ожидающая появления цена WB с Кошельком читается без резервного запроса к API обычной цены;
- мост принимает только `wb_wallet`, отклоняет `wb_product` и WB JSON с обычной ценой; уведомление подписано «по WB Карте (с WB Кошельком)»;

- диагностика запускает актуальный файл через `chrome.scripting`, не использует старый обработчик вкладки и не требует связи с desktop; неподдерживаемая вкладка, запрет запуска и пустой результат дают понятные сообщения;
- popup не отображает `undefined`, корректно показывает отчёт и ошибку ответа; сетевая ошибка loopback объясняется отдельно от ошибки площадки.

Цена проверена на переданном пользователем фрагменте, а не на полной живой карточке. Полная установка расширения в облачном Chromium запрещена администратором; её проверка остаётся на домашней VM. Новый EXE и расширение требуют версии 0.4.2 вместе. Windows-упаковка и графические тесты выполняются GitHub Actions, готовность артефакта определяется результатом конкретного workflow.

- появление видимой цены после отказа резервного API 403, ограничение общим бюджетом времени, сохранение проверки продавца, отсутствие автоматического объявления CAPTCHA по одному отказу API.

Скриншот пользователя подтверждает внешний вид блока WB, но не CSS-классы его живой страницы. Новое правило проверено на синтетической разметке; работу на карточке `708052242` после обновления ещё нужно подтвердить на домашней VM. Для этого добавлена кнопка диагностики открытой карточки в расширении. Она выводит только данные распознавания блока цены и не делает запросов к API площадки.

Windows EXE собирается и проверяется в GitHub Actions. Локальные проверки не подтверждают готовность Windows-артефакта или работу установленного расширения в пользовательском браузере. Ограничение облачного браузера описано ниже.

Обновление расширения 0.2.1: воспроизведены и исправлены два случая чтения DOM — подпись оплаты, разбитая вложенными элементами, и скрытая цена, которую нельзя принимать за видимую. Проверены синтаксис JavaScript, ruff и компиляция Python.

Тесты локального HTTP-моста проверяют loopback-привязку, код подключения и Origin, одноразовое задание, SKU, тип цены, паузы и невозможность повторного события. Тест в Chromium выполняет настоящий JavaScript извлечения видимой цены из синтетического DOM с подписью Ozon Карты и «без WB Кошелька». Это не реальные ответы площадок.

Новая Windows-сборка и новые графические clipboard-тесты проверяются через конкретный запуск GitHub Actions. До получения его результатов они не считаются пройденными.
