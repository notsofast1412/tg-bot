# Проверки Windows-версии 0.4.0

Локально в Linux/Python 3.12 с Chromium: 71 Python-тест, 67 пройдено, 4 графических теста пропущены; 23 JavaScript-теста пройдены. Ruff, форматирование, компиляция Python и `git diff --check` пройдены.

Дополнительно проверены:

- разовый обход при остановленном расписании и сроке следующей проверки через сутки, учёт активной проверки без дубликата, сохранение обхода после перезапуска;
- остановка разового обхода, исключение товаров на паузе, сохранение HTTP 429, завершение неуспешной/просроченной попытки без бесконечных повторов;
- добавление своего тега, его применение к товару, сохранение после перезапуска и защита от перезаписи существующего порога;
- миграция баз версий 1 и 2 в схему 3 с backup и сохранением активного задания;
- WB с тремя ценами 261/270/379 ₽: в fixture DOM с отдельными ролями кошелька, основной и старой цены возвращается 270 ₽; скрытые, зачёркнутые, вложенные и неоднозначные роли отклоняются;
- появление видимой цены после отказа резервного API 403, ограничение общим бюджетом времени, сохранение проверки продавца, отсутствие автоматического объявления CAPTCHA по одному отказу API.

Скриншот пользователя подтверждает внешний вид блока WB, но не CSS-классы его живой страницы. Новое правило проверено на синтетической разметке; работу на карточке `708052242` после обновления ещё нужно подтвердить на домашней VM. Для этого добавлена кнопка диагностики открытой карточки в расширении. Она выводит только данные распознавания блока цены и не делает запросов к API площадки.

Windows EXE собирается и проверяется в GitHub Actions. Локальные проверки не подтверждают готовность Windows-артефакта или работу установленного расширения в пользовательском браузере. Ограничение облачного браузера описано ниже.

## История версии 0.3

27 октября 2026 года: локальные проверки в Linux/Python 3.12 с системным Chromium. 61 Python-тест: 57 пройдено, 4 графических теста пропущены без desktop-сеанса. 21 JavaScript-тест пройден. Ruff, форматирование, проверка зависимостей и `git diff --check` пройдены.

Проверено дополнительно:

- 200 товаров при нулевом интервале, включая одинаковую секунду всех результатов: ни одна карточка не остаётся без слота;
- конкурентные запросы нескольких клиентов через настоящий локальный HTTP: глобальный лимит, уникальность товара, немедленное заполнение освободившегося слота;
- реальное перекрытие четырёх проверок в асинхронном тесте расширения, чтение до завершения изображений, ограничение зависшего чтения;
- расширение 0.3.1 закрывает временные вкладки при успехе и ошибке/таймауте, убирает записанные оставшиеся вкладки после остановки service worker, сохраняет переиспользованные пользователем вкладки, заново открывает карточку для ручной проверки;
- настоящий MutationObserver в Chromium читает динамически появившуюся цену без резервного API;
- интервалы 0 и 1 секунда, сохранение задания после перезапуска, истечение, удаление и остановка;
- параллельная ошибка не сокращает ранее установленный Retry-After, ручная кнопка не снимает HTTP 429;
- миграция схемы 1 → 2 с резервной копией и сохранением товаров, настроек, истории, очереди;
- уведомления о цене при непрерывном обходе и повторная проверка условия перед отправкой при конкурентном изменении цены;
- команды владельца в ЛС, запрет управления из группы/чужого аккаунта, безопасная выдача собственного ID, пропуск старых команд и защита от повторного исполнения;
- добавление и подтверждаемое удаление, пороги, паузы, интервал, параллельность, сводка 200 ошибок, сохранение ограничения повторов после перезапуска, повтор явно отклонённой отправки и отсутствие немедленного повтора при потерянном ответе.

Все карточки/ответы Telegram в этих тестах синтетические. Время тестов не означает скорость проверки настоящих 200 карточек. Живые цены WB/Ozon и команды/ЛС с пользовательским токеном в этой среде не проверялись. Windows EXE собирается и проверяется отдельным workflow GitHub Actions; результат нужно смотреть по конкретному запуску. Полная установленная связка расширения здесь недоступна из-за административного запрета загрузки unpacked-расширений в облачном браузере, как описано ниже.

## История версии 0.2

Обновление расширения 0.2.1: воспроизведены и исправлены два случая чтения DOM — подпись оплаты, разбитая вложенными элементами, и скрытая цена, которую нельзя принимать за видимую. После исправления прошли 7 браузерных fixture-тестов и 11 JavaScript-тестов. Дополнительно проверено различение отказа API, настоящей страницы проверки и обычного ответа без JSON. Эти проверки не подтверждают получение цены с живой карточки WB `708052242`: из облачной среды она возвращает HTTP 498 WBAAS без товарной разметки.

27 октября 2026 года, МСК: 40 Python-тестов, 36 пройдено, 4 проверки окна пропущены в Linux без графического сеанса. Семь JavaScript-тестов проверяют точность цены, отсутствие подмены обычной ценой, выдачу заданий, остановку при паузе и сохранность пользовательской вкладки. Проверены синтаксис JavaScript, ruff и компиляция Python.

Тесты локального HTTP-моста проверяют loopback-привязку, код подключения и Origin, одноразовое задание, SKU, тип цены, паузы и невозможность повторного события. Тест в Chromium выполняет настоящий JavaScript извлечения видимой цены из синтетического DOM с подписью Ozon Карты и «без WB Кошелька». Это не реальные ответы площадок.

В тестовом управляемом Chromium этой облачной среды загрузка распакованного расширения запрещена администратором (`Loading of unpacked extensions is disabled by the administrator`). Политика не менялась. Поэтому полная связка установленного расширения, браузера и приложения здесь не проверена. Её ещё нужно проверить на домашней Windows-VM, где пользователь подтвердил доступность обеих карточек в обычном Chrome.

Новая Windows-сборка и новые графические clipboard-тесты проверяются через конкретный запуск GitHub Actions. До получения его результатов они не считаются пройденными.

## История проверки версии 0.1

Проверено 27 октября 2026 года, МСК. Локальная среда: Linux, Python 3.12.14, системный Chromium. Это не пользовательская Windows-VM.

Команда: `PAINTWATCH_TEST_BROWSER=/usr/bin/chromium .venv/bin/python -m unittest discover -s tests -v`.

Результат: 31 тест, 29 пройдено, 2 проверки окна пропущены из-за отсутствия графического сеанса. `ruff check`, `ruff format --check`, проверка компиляции Python и `pip check` прошли.

Проверены:

- ссылки, артикулы, пакетное добавление, дубликаты и точные денежные единицы;
- цена Ozon только по карте, SKU, продавец, размер и остаток WB;
- строгое пересечение порога, первое событие, отсутствие повторов ниже порога, сохранение состояния при ошибках;
- редактирование порогов, индивидуальные исключения, пауза и удаление;
- SQLite backup, восстановление неопределённой отправки после аварии, блокировка второго экземпляра;
- очередь Telegram, успешная отправка, неизвестный результат, RetryAfter и запрет отправки по устаревшей/неуспешной проверке;
- планировщик и сохранение следующего срока после перезапуска;
- четыре сценария настоящего Chromium с перехваченными синтетическими ответами: чтение Ozon в той же сессии, использование ответа страницы WB, остановка при CAPTCHA, отсутствие нового запроса приложения после HTTP 429.

Браузерные тесты не обращаются к маркетплейсам и не подтверждают доступ к настоящим ценам. Контейнерный тестовый браузер работает headless с настройками Playwright для тестовой среды. Продуктовый браузер запускается с видимым окном и включённым Chromium sandbox.

В workflow `Windows application` добавлены тесты Windows/Linux, проверка окна, реального Windows DPAPI и smoke test упакованного EXE. Их выполнение и готовность артефакта нужно проверять по результату конкретного запуска Actions; локальная проверка их не заменяет. PowerShell-установщик и Windows-упаковка в этой Linux-среде не выполнялись.

На домашней Windows-VM остаются проверки: живые WB/Ozon, реальная цена по карте, сохранение ручной сессии, отправка в нужную Telegram-группу, трей, автозапуск и работа после перезагрузки/отключения RDP. На момент этой проверки они не выполнены.
