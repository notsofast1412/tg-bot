# Фактические результаты проверок

Проверено 19 октября 2026 года, МСК. Среда разработки — Python 3.12.14, исходники в `/workspace/tg-bot`. Зависимости установлены из зафиксированного файла с хешами. Результаты относятся к текущей машине и версии кода, не к ещё не установленной службе Ubuntu.

## Автоматические проверки

`python -m pytest -q`: **105 passed**, 0 failed, 0 skipped. Используются моки внешних сервисов, SQLite во временных каталогах и минимизированный реальный ответ Ozon как фиксированный пример схемы.

Покрыты:

- Ссылки WB/Ozon, прямой числовой артикул, выбор площадки и обязательный предпросмотр; отказ от неоднозначных буквенных артикулов без поиска аналогов.
- URL без пробелов, пакеты, частичные ошибки и дубликаты; сохранение только после подтверждения; отмена, истечение и восстановление сценария.
- Все 16 тегов и сумм из ТЗ, повторный seed без сброса настроек, индивидуальные пороги.
- Строгие границы цены, первое уведомление, отсутствие повторов внутри условия, новый переход после роста; сохранение состояния при ошибках.
- Несовпадение карточки, устаревшие данные, смена продавца; сохранение уточнений владельца.
- WB JSON, Ozon composer JSON с приоритетом `cardPrice`, HTTP JSON-LD, маршрутизация резервного Playwright. Для Ozon общий JSON-LD не принимается за подтверждённую цену по карте.
- Запрет обращения по посторонним ссылкам/редиректам, ограничения доступа, кешированный ответ, `Retry-After` и сохранение паузы после перезапуска.
- Изоляция ошибок площадок, расписание и запрет параллельных проверок, запуск/остановка цикла и backup.
- Проверка владельца и личного чата для сообщений и callback, игнорирование групп, защита от повторной обработки update.
- Диспетчеризация настоящего aiogram Dispatcher, меню, фильтры и история; диагностика и тестовая отправка с моками Telegram.
- Транзакционная очередь, успешная отправка, явный отказ, `RetryAfter`, автоматический повтор до отправки при недоступности API, неизвестный результат после отправки и ручной подтверждённый повтор.
- Отмена устаревшего уведомления после восстановления цены и ожидание свежей цены после ошибки.
- Миграции Alembic с нуля и повторно, отсутствие расхождения моделей и схемы, SQLite integrity check, согласованный backup при открытом WAL, восстановление через CLI, lock одного экземпляра и маскирование токенов.

Дополнительно прошли `ruff check`, `ruff format --check`, `pip check`, `bash -n scripts/*.sh`. Unit systemd проверен `systemd-analyze verify` на временной копии с заменой `/opt/paintwatch` на путь текущего checkout и пользователя на текущего; production unit и установка в `/opt` здесь не запускались.

Системный Chromium фактически запущен через Playwright, выполнен JavaScript на локальном тестовом HTML. При отдельной диагностике HTTPS-навигации Chromium остановился на `ERR_CERT_AUTHORITY_INVALID`. Подтверждено по журналу: браузер не может открыть существующее NSS-хранилище на запись (`SEC_ERROR_READ_ONLY`, -8126) и запускается без него. Сертификат прокси уже есть в этом хранилище; новый импорт не требуется. Ранее предложенный импорт был отклонён автоматической проверкой безопасности и не выполнялся. Получение данных WB/Ozon через браузер не подтверждено; проверки TLS не отключались. Обход ограничений площадок не тестируется и не реализован.

Объём и количество упаковки на проверенной карточке Ozon в разобранных структурированных характеристиках отсутствовали; бот оставляет их неизвестными и предлагает уточнение. `520 мл` из названия не становится автоматически подтверждённым полем комплектации.

Разовые цены приведены с датой проверки и могут измениться. Реальные запросы выполнялись обычным HTTPS без авторизации, CAPTCHA-обхода, отключения TLS или подмены ответа заглушкой.

## Что осталось проверить на целевой установке

1. Ввести Telegram-токен безопасно, задать ID владельца, запустить процесс и настроить группу через `/setgroup`.
2. Выполнить фактическую диагностику и тестовую отправку из личного чата владельца.
3. Подтвердить допустимый доступ WB с целевого сервера/разрешённого источника. Текущие 403/498 остаются внешним ограничением; получение цен WB не заявлено работающим.
4. Установить и запустить systemd на Ubuntu 24.04, проверить перезагрузку и наблюдать реальные циклы в течение нужного периода. В облачной среде systemd-служба на пользовательском сервере не установлена.

В черновике облачной среды сохранены требования к сетевым доменам, `BOT_TOKEN` и `OWNER_ID`; инструкции установки/старта сохраняются отдельно. Сохранение черновика не означает ввод credentials, публикацию среды или успешную доставку.
