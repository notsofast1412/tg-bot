# Установка и проверка Windows-версии

## Домашняя виртуалка

Windows 11 x64, 2–4 vCPU, 8 GB RAM, SSD 64–80 GB, VirtIO-сеть через домашний bridge. Установите драйверы VirtIO и Edge или Chrome. Нужен исходящий HTTPS к площадкам и `api.telegram.org`; входящие порты не требуются.

Программа работает в сеансе пользователя, не как служба. После перезагрузки требуется вход в Windows. Отключение RDP не должно завершать сеанс; выход из Windows завершает его. Проверьте сон и поведение VM после перезапуска Proxmox.

## Данные

В `%LOCALAPPDATA%\PaintWatch`:

- `prices.sqlite3` и WAL — товары, настройки, история, очередь;
- `profiles\ozon`, `profiles\wb` — старые профили режима Playwright (версия 0.3 по умолчанию их не использует);
- `telegram.dpapi` — зашифрованный токен текущего пользователя Windows;
- `extension.dpapi` — защищённый код подключения расширения;
- `backups` — автоматические копии базы;
- `app.lock` — блокировка второго экземпляра.

При переезде под другого пользователя заново введите токен и пройдите проверку в новом профиле. SQLite backup не включает browser cookies или токен. На Linux для разработки токен хранится только в памяти.

## Реальная проверка

1. Добавьте `https://www.ozon.ru/product/196525150/` и `https://www.wildberries.ru/catalog/29220564/detail.aspx`. До первого успеха цена должна быть неизвестна, а не ноль.
2. Установите расширение по [инструкции](extension.md), подключите его и включите мониторинг. При необходимости пройдите проверку в обычном браузере и нажмите «Я прошёл проверку» в приложении.
3. Сверьте SKU, вариант, продавца и цену. WB сравнивается с ценой по WB Кошельку, Ozon — только по карте; обычная цена и JSON-LD `Offer.price` её не заменяют. Регион и способ оплаты могут влиять на результат.
4. Изменившийся или неподтверждённый продавец останавливает обновление цены. Проверьте карточку, при необходимости удалите товар и добавьте подтверждённую карточку заново.
5. Отправьте тест в Telegram. Для проверки настоящего события задайте порог на тестовом товаре до первой проверки: первая подтверждённая цена ниже порога создаст событие. Изменение порога после получения цены само по себе рассылку не вызывает.
6. Завершите через «Выход» и запустите снова. Проверьте товары, настройки, профиль, историю и очередь. Повторная такая же цена не должна создать новое событие. Снижение на 14,99 ₽ от последнего отправленного значения не вызывает повтор, снижение на 15 ₽ вызывает.
7. Проверьте трей, автозапуск после входа в Windows и работу после перезагрузки VM. Реальные результаты не заменяются тестами на заглушках.

При 403/498 основной страницы, CAPTCHA или `fab_chlg` сохраняется пауза площадки. Отказ только резервного API не означает CAPTCHA на основной странице. «Я прошёл проверку» разрешает новую попытку после ручного подтверждения, но не отменяет HTTP 429. «Проверить по расписанию» использует выбранный интервал в секундах. Частые повторные нажатия не восстанавливают доступ.

## Доставка

Для отправки нужна успешная последняя завершённая проверка не старше 15 минут. Старое событие дождётся свежей проверки. Остановленный мониторинг не рассылает очередь автоматически.

«Результат неизвестен» не повторяется автоматически: проверьте номер события в группе и при необходимости подтвердите повтор. После неизвестного сетевого результата или восстановления старой базы возможен дубликат — это ограничение внешнего API.

Личное управление и сообщения о проблемах: [telegram.md](telegram.md). После сохранения токена отправьте боту `/id`, затем укажите полученный ID в настройках.

Кнопка «Проверить все сейчас» запускает разовый обход включённых товаров вне расписания. Если расписание остановлено, цены обновляются, рассылка ценовых событий остаётся на паузе. Создание своих тегов доступно на вкладке «Теги и пороги».

Текущая связка: приложение **0.4.10**, расширение **0.4.8**. Из **PaintWatch-Windows-x64** обновите всю папку программы после завершения через «Выход», затем запустите новый EXE. Обновите папку расширения, нажмите ↻ в Chrome и при запросе разрешите блокировку запросов (`declarativeNetRequest`). В расширении включена экономия фото и видео только для проверочных вкладок; её можно выключить. База и токены сохраняются отдельно, схема SQLite остаётся версии 4. После сообщения с числовым артикулом бот по-прежнему спрашивает площадку и тег.

Для 621 товара на ВМ с 4 vCPU и 8 ГБ начните с 6 параллельных проверок и лимита 25 секунд. Интервал 0 даёт непрерывный обход; 500 секунд оставляют минимум 8 минут 20 секунд между повторными попытками одного товара. Через пять минут сравните темп и возраст старейшего результата в `/status`. Сохранённые значения обновление не меняет. Реальную скорость и загрузку CPU/RAM нужно измерить на ВМ; локальные тесты не подтверждают производительность живых карточек.

Автоочистка в расширении 0.4.8 раз в 30 минут оставляет одну вкладку PaintWatch и закрывает остальные вкладки этого профиля, включая личные и закреплённые. На время очистки новые проверки приостанавливаются; начатые завершаются по обычному таймауту. Флажок можно выключить в расширении, кнопка «Очистить вкладки сейчас» запускает очистку вручную. Если EXE уже 0.4.7, достаточно заменить содержимое загруженной папки расширения из артефакта **PaintWatch-extension** и нажать ↻ в Chrome.

Расширение возвращено к коду **0.4.8** по сообщению пользователя о сбое Ozon в 0.4.9. Для отдельного отката скачайте **PaintWatch-extension**, замените всё содержимое загруженной папки расширения и нажмите ↻ в Chrome. Перезагрузите открытые карточки. Приложение 0.4.10 и команды упоминаний сохраняются.

Для `/tagall` требуется обновление приложения до 0.4.10: скачайте **PaintWatch-Windows-x64**, завершите PaintWatch через «Выход» и замените всю папку программы с `_internal`. Расширение остаётся 0.4.8. Данные сохраняются отдельно; добавлены таблицы списка участников и задания упоминаний, схема SQLite совместима с версией 4. Сделайте бота администратором настроенной группы; молчаливым старым участникам нужно один раз отправить `/here`.

## Backup

Ручной и суточный backup используют SQLite Backup API. Остаются 14 автоматических копий; ручные не удаляются. Для защиты от потери диска храните копии за пределами VM.

Для восстановления полностью завершите PaintWatch, сохраните текущую папку данных отдельно и проверьте backup. Замените базу остановленного приложения согласованным файлом backup; прежние WAL/SHM оставьте только в сохранённой копии, не рядом с восстановленной базой. Перед включением мониторинга проверьте очередь: backup не знает об отправках после своего создания.

## Локальная сборка

Обязательные проверки GitHub Actions выполняются на `windows-2022`: Python, JavaScript расширения, Ruff, окно приложения и DPAPI. Успешные проверки разрешают упаковку и запуск готового EXE. Отдельного обязательного задания Ubuntu нет. При ошибке тестов скачайте артефакт **PaintWatch-test-logs** с полным выводом Python/JavaScript; это журнал, а не сборка программы.

С Python 3.12 x64 в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Передавайте всю папку `dist\PaintWatch`, включая `_internal` и `extension`. Для обновления завершите программу через «Выход» и замените исходники/EXE, сохранив папку данных. После обновления папки расширения нажмите «Обновить» на его карточке в Chrome. Изменение страницы площадки может потребовать обновления распознавания цены и повторной проверки адаптера.
